# Provider Optimization Gap Matrix

Status: v1 planning matrix
Ticket: 06FBSC4HSXFJ5FM6GWECH2CTGG

## Purpose

This document turns the current provider optimization evidence into a prioritized backlog matrix for later save and read strategy work. It uses [Provider Optimization Evidence Matrix](provider-optimization-evidence-matrix.md) as the canonical row lookup surface and cites the checked-in benchmark and architecture documents instead of restating raw benchmark output.

The matrix separates capability gaps from evidence gaps:

- PostgreSQL, MySQL, and DB2 `latest-satellite-read` rows are capability gaps because the checked-in guidance rows record `providerSpecificReadStrategy=not registered for latest satellite reads`.
- SQL Server and Oracle `latest-satellite-read` rows plus PostgreSQL, SQL Server, MySQL, Oracle, and DB2 `provider-native-bulk-ingestion`, `pit-as-of-read`, and `bridge-traversal-read` rows are evidence gaps because provider strategy posture is already visible, but the root benchmark triplet keeps those optional-provider rows as skipped placeholders when connection strings are unset.
- DB2 rows keep the narrower v0.34.0 boundary: clean-context save and PIT/bridge candidate behavior may be cited from diagnostics and smoke evidence, but no completed DB2 timing, latest-satellite optimization, staged DB2 bulk, or provider-native chunk execution is claimed.

## Ordering Rules

Priorities are deterministic and repository-backed:

1. `P0` rows are latest-satellite follow-ups: PostgreSQL, MySQL, and DB2 remain capability gaps, while SQL Server and Oracle are retained as evidence-gap rows until configured timing exists.
2. `P1` rows are external-provider save timing-evidence gaps, using the same provider order.
3. `P2` rows are external-provider PIT as-of timing-evidence gaps, using the same provider order.
4. `P3` rows are external-provider bridge traversal timing-evidence gaps, using the same provider order.

SQLite completed timing rows are reference baselines, not backlog gaps.

## Follow-Up Split Guidance

Future tickets should split by gap family:

- Strategy-expansion work: `P0` PostgreSQL, MySQL, and DB2 latest-satellite capability gaps.
- SQL Server and Oracle latest-satellite timing collection: `P0.02` and `P0.04` evidence follow-ups when configured benchmark lanes are available.
- Save evidence work: `P1` provider-native bulk ingestion timing gaps.
- Read evidence work: `P2` PIT and `P3` bridge timing gaps.

Do not combine capability design with external-provider timing collection unless the ticket also provisions the exact provider, connection-string gate, benchmark artifact triplet, diagnostics evidence, and finite fallback behavior needed for that provider and scenario.

## Non-Goals

This matrix does not add provider strategies, benchmarks, release notes, runtime code, package publication records, external database provisioning, credentials, raw SQL artifacts, automatic PIT or bridge maintenance, provider-specific physical-design claims, or external-provider timing claims from skipped, diagnostics-only, smoke-only, or storage-footprint evidence.
