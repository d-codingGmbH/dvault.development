# DVault v0.37.0 Release Notes

Release: `v0.37.0 - Dependency Line and Analyzer Compatibility`
Release date: 2026-06-13

These notes define the v0.37.0 coordinated package and documentation baseline for the DVault package compatibility lines visible in the repository. They record the eight-package family, the supported consumer package-version lines, the accepted target-specific dependency matrix, the analyzer build-host compatibility boundary, carried-forward validation evidence, and explicit non-goals. They do not record a NuGet push, package hashes, final publication links, release approval, release automation, a runtime behavior change, or a new analyzer target asset. The final approval record described by [Manual NuGet Publication Checklist](../manual-nuget-publication.md#final-approval-record) remains the publication authority before any package is pushed.

## Package Scope

This is a coordinated release record for the eight-package DVault NuGet family:

- `DCoding.Data.DVault`
- `DCoding.Data.DVault.Analyzers`
- `DCoding.Data.DVault.Db2`
- `DCoding.Data.DVault.MySql`
- `DCoding.Data.DVault.Oracle`
- `DCoding.Data.DVault.Postgres`
- `DCoding.Data.DVault.Sqlite`
- `DCoding.Data.DVault.SqlServer`

The `src/DCoding.Data` project remains a non-packable source-root build anchor for the namespace family and is not a NuGet publication artifact.

The release tag and release-note label `v0.37.0` is not a consumer-facing NuGet package version. Current repository package inputs still expose these aligned consumer package-version lines:

| Package version line | Target framework | EF Core line |
| --- | --- | --- |
| `8.37.0` | `net8.0` | EF Core 8 |
| `10.37.0` | `net10.0` | EF Core 10 |

Do not publish or document a consumer-facing `0.37.0` package version from this release label. Do not combine `8.37.0` and `10.37.0` packages in one consumer project, one install example, one restored target, or one publish approval.

## Analyzer Compatibility

`DCoding.Data.DVault.Analyzers` remains one `net10.0` analyzer package asset for both coordinated consumer package lines. Analyzer references must stay local to the declaration-owning project with `PrivateAssets="all"`.

Supported analyzer consumption for both `8.37.0` and `10.37.0` uses a `.NET 10 SDK` build host. This includes `net8.0` consumer projects on the `8.37.0` package line. The repository does not validate pure `.NET 8 SDK` analyzer consumption, and this v0.37.0 record does not broaden the compatibility claim to that baseline.

The analyzer package supplies build-time analyzers and source generators under analyzer package conventions. It does not require a runtime reference from application code and does not add consumer-target-specific runtime assets for `net8.0` or `net10.0`.

## Carried-Forward Baselines

v0.37.0 moves the current documentation baseline forward for dependency-line and analyzer compatibility while carrying forward the v0.36.0 binary hash-key storage adoption guidance, the v0.35.0 stable hash algorithm-selection baseline, the v0.34.0 DB2 provider package baseline, the v0.33.0 dual `net8.0` / `net10.0` compatibility contract, the v0.32.0 benchmark-driven provider threshold evidence and review-only SQL artifact manifest lane, the v0.31.0 performance decision-tree and observability baseline, the v0.30.0 typed helper support-bundle freshness baseline, the v0.29.0 provider schema guardrail baseline, the v0.28.0 provider read optimization evidence boundary, the v0.27.0 EF lifecycle analyzer guardrails, the v0.26.0 provider-tuning diagnostics and benchmark verifier evidence, the v0.25.0 ReadShape and typed helper boundary, the v0.24.0 async streaming and EF safety boundary, and the v0.21.0 PIT/bridge maintenance boundary.

The carried-forward hash-key storage baseline still keeps logical hash-key values as lowercase hexadecimal strings at public request, save, read, diagnostics, and support-bundle boundaries. `HexString` remains the default compatible physical storage profile, and `Binary` remains an explicit opt-in physical storage profile for generated hash-key columns when an application has planned storage, migration, indexing, and operational evidence for that database. Existing `HexString`-compatible databases and configurations remain valid until the application owner intentionally plans and executes a separate reviewed migration, reset, or data-move change. DVault does not automatically rehash, backfill, dual-write, repair, or migrate persisted hash-key storage when the storage profile or stable hash algorithm changes.

## Limitations And Non-Goals

v0.37.0 aligns project `PackageReference` values, provider pins, matrix tests, package verifier expectations, package-line versions, and documentation around the accepted target-specific dependency baselines. In particular, `net8.0` references stay on the EF Core 8/provider 8.x line and `net10.0` references stay on the EF Core 10/provider 10.x line. The release does not change analyzer target frameworks or runtime behavior.

v0.37.0 does not publish packages, record final publish approval, record package hashes, add package-signing evidence, add release automation, or change the manual publication stop conditions.

v0.37.0 does not claim a consumer-facing `0.37.0` package version. It documents the repository-visible `8.37.0` and `10.37.0` consumer package lines.

v0.37.0 does not validate pure `.NET 8 SDK` analyzer consumption. If that becomes a product requirement, the analyzer asset target and verification lane must change explicitly.

v0.37.0 does not change the runtime default stable hash algorithm, hash-key storage profile, provider-side hashing behavior, persisted-key migration posture, DB2 live-schema support, provider provisioning, or external database test requirements.
