# DVault v0.6.0 Release Notes

Release: `v0.6.0 - Code-First Usability Flow`
Intended release date: 2026-05-11

## Package Scope

This is a coordinated release for the six-package DVault NuGet family:

- `DCoding.Data.DVault`
- `DCoding.Data.DVault.MySql`
- `DCoding.Data.DVault.Oracle`
- `DCoding.Data.DVault.Postgres`
- `DCoding.Data.DVault.Sqlite`
- `DCoding.Data.DVault.SqlServer`

All packages are version-aligned at `0.6.0`.

## Highlights

- Added the Code-First EF model declaration flow as the recommended README schema-declaration path for hubs, hub-parent satellites, multi-active driving keys, and ordered hub links through `ApplyDataVaultMetadata(vault => ...)`.
- Documented the public Code-First builder surface: `Hub<TEntity>()`, `BusinessKey(...)`, `Satellite(...)`, `Payload(...)`, `DrivingKey(...)`, `Link(...)`, and `Participant<TEntity>()`.
- Kept the explicit persistence boundary visible: callers still save through `IDataVaultSaveService`, pass load timestamps and record sources in `DataVaultSaveRequest`, and choose when vault rows are written.
- Added typed latest/as-of satellite read helpers that project `IDataVaultReadService` results through caller-owned delegates for common read models.
- Preserved raw `ReadLatestSatelliteRowsAsync(...)` reads as the advanced row-level escape hatch for custom projections and dictionary-shaped payload handling.
- Preserved metadata-first `DataVaultMetadataModel` usage and registry-backed `UseDataVaultMetadata()` as compatible paths for shared schema, save, and read metadata, examples, and advanced usage.
- Added diagnostics and explain output coverage for metadata models, metadata registries, Code-First declarations, and configured DbContexts.
- Added runnable SQLite and PostgreSQL quickstarts that use one shared registry-backed metadata model, explicit saves, and typed latest/as-of reads.
- Updated the local external-provider validation baseline to MySQL 9.7, PostgreSQL 18, SQL Server 2025, and current EF provider client packages where available.

## Compatibility Notes

- v0.5 metadata-first `DataVaultMetadataModel` usage remains compatible in v0.6.0. Existing applications can keep registering metadata with `AddDVault(options => options.UseMetadataModel(...))` and opting DbContexts into `UseDataVaultMetadata()`.
- Code-First declarations are the recommended new README schema-declaration flow where the implemented hub, hub-parent satellite, multi-active driving-key, and ordered hub-link surface fits the application model.
- Registry-backed metadata remains the recommended v0.6.0 path when callers want one public metadata source reused by schema projection, explicit saves, and latest/as-of reads.
- Registry-backed metadata remains the documented path for shared metadata and for the runnable SQLite and PostgreSQL quickstart projects.
- There is no public Code-First-to-registry conversion API in v0.6.0. Do not present Code-First declarations as an authoritative registry source for `UseDataVaultMetadata()`.
- Typed satellite reads use caller-supplied projector delegates. They do not add reflection-based DTO binding or a model-first projection contract.
- `IDataVaultReadService` remains scoped to latest/as-of satellite rows by parent hash key. Raw row reads remain available when callers need `DataVaultSatelliteReadRecord` details directly.
- Diagnostics validation and explain output can run without a save request. Provider-specific save-strategy dispatch diagnostics are request-bound, and validation-only analysis keeps save-strategy status not evaluated.
- Provider-specific save strategies may still decline unsupported request shapes and fall back to the provider-neutral writer.

## Known Limitations

- Model-first import/export specs are not delivered in v0.6.0.
- PIT-backed read APIs are not delivered in v0.6.0.
- Bridge traversal read helpers are not delivered in v0.6.0.
- PIT and bridge row maintenance are not delivered in v0.6.0.
- Provider-specific read optimizations are not delivered in v0.6.0.
- A public Code-First-to-registry bridge is not delivered in v0.6.0.
- Link-parent satellite Code-First declarations remain outside the bounded v0.6.0 Code-First surface and can continue to use metadata-first declarations.
