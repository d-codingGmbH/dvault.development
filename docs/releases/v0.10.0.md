# DVault v0.10.0 Release Notes

Release: `v0.10.0 - Developer Adoption Tooling`
Intended release date: 2026-05-15

## Package Scope

This is a coordinated release for the seven-package DVault NuGet family:

- `DCoding.Data.DVault`
- `DCoding.Data.DVault.Analyzers`
- `DCoding.Data.DVault.MySql`
- `DCoding.Data.DVault.Oracle`
- `DCoding.Data.DVault.Postgres`
- `DCoding.Data.DVault.Sqlite`
- `DCoding.Data.DVault.SqlServer`

All packages are version-aligned at `0.10.0`. Package publication remains a separate manual release activity; these notes do not record a NuGet push, package hashes, or final publication links.

## Highlights

- Added the packable `DCoding.Data.DVault.Analyzers` Roslyn analyzer package.
- Added analyzer diagnostic `DMV1901` for unsupported Code-First selector shapes in `BusinessKey(...)`, `Payload(...)`, and `DrivingKey(...)`.
- Added analyzer diagnostic `DMV1902` for duplicate logical member declarations inside one relevant Code-First fluent scope.
- Added analyzer tests that cover true positives and false-positive guards for valid direct readable scalar selectors, separate satellite scopes, and selector variables outside the first direct-lambda slice.
- Added PostgreSQL local container fixture guidance for Podman and Docker, using `docker.io/postgres:18` and `DVAULT_TEST_POSTGRES_CONNECTION_STRING`.
- Refreshed adoption documentation around NuGet installation, provider setup, quickstarts, production readiness, migration and drift guardrails, and manual publication.
- Extended package verification to include the analyzer package and analyzer assets in the coordinated release gate.

## Analyzer Package

`DCoding.Data.DVault.Analyzers` is developer tooling, not a runtime dependency. Consumer projects should reference it with `PrivateAssets="all"` so analyzer assets stay local to the project that owns DVault Code-First declarations:

```xml
<PackageReference Include="DCoding.Data.DVault.Analyzers" Version="0.10.0" PrivateAssets="all" />
```

The first analyzer slice is intentionally narrow and high-confidence:

- `DMV1901` reports unsupported selector shapes such as anonymous-object selectors, method calls, nested member selectors, and collection-valued selectors when used as the first direct lambda argument to supported Code-First fluent methods.
- `DMV1902` reports duplicate logical member names within the same applicable `BusinessKey(...)`, `Payload(...)`, or `DrivingKey(...)` fluent scope.

The analyzer package does not provide code fixes, full model validation, model-first JSON validation, provider diagnostics, migration guardrails, or dataflow analysis in this release.

## Provider Fixture Guidance

The PostgreSQL quickstart now includes local fixture guidance for developers who want a repeatable external-provider proof:

- start a developer-managed PostgreSQL 18 container with Podman or Docker;
- configure `DVAULT_TEST_POSTGRES_CONNECTION_STRING`;
- run the PostgreSQL quickstart;
- run the opt-in Postgres integration tests with `Category=ProviderIntegration.ExternalOptIn&Provider=Postgres` and the non-secret MSBuild marker `-p:DVAULT_TEST_POSTGRES_CONNECTION_STRING=Configured`;
- clean up the local container.

Default build and test execution still requires no external database, Docker, or Podman dependency.

## Documentation Updates

- Root README installation guidance now includes the analyzer package and aligned `0.10.0` package examples.
- `examples/README.md` keeps the SQLite quickstart as the no-container local baseline and links the PostgreSQL fixture path as opt-in external evidence.
- `docs/production-adoption-checklist.md` now reflects the seven-package coordinated family and marks analyzer usage as project-local developer tooling.
- `docs/manual-nuget-publication.md` now treats the analyzer package as part of the coordinated manual publication family and package-verification gate.

## Compatibility Notes

- Runtime DVault persistence behavior is unchanged by the analyzer package.
- Provider packages still depend on the aligned `DCoding.Data.DVault` package version.
- The analyzer package has no provider dependency and should not become a transitive runtime dependency of application packages.
- Existing `IDataVaultSaveService`, typed read helpers, provider save strategies, model-first governance APIs, and opt-in `SaveChanges` metadata interceptor behavior remain unchanged.

## Known Limitations

- Analyzer coverage is limited to the first Code-First selector-shape and duplicate-member rules.
- The analyzer does not inspect metadata-first registries, model-first JSON artifacts, migration operations, provider tuning, or generated SQL.
- PostgreSQL is the only documented external provider container fixture in this release. SQL Server, Oracle, and MySQL remain opt-in external database paths without first-class fixture docs.
- SQLite remains the first-class live-schema drift reader. Other providers still rely on external opt-in evidence for live database validation.
