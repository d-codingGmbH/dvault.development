# DVault v0.5.0 Release Notes

Release: `v0.5.0 - Provider Optimizations and Deferred Capabilities`
Intended release date: 2026-05-09

## Package Scope

This is a coordinated release for the six-package DVault NuGet family:

- `DCoding.Data.DVault`
- `DCoding.Data.DVault.MySql`
- `DCoding.Data.DVault.Oracle`
- `DCoding.Data.DVault.Postgres`
- `DCoding.Data.DVault.Sqlite`
- `DCoding.Data.DVault.SqlServer`

All packages are version-aligned at `0.5.0`.

## Highlights

- Added provider-specific save strategies for the existing provider package family, with provider-neutral fallback when a provider strategy declines the current context or request shape.
- Added load-timestamp storage projection options for provider default, ISO 8601 UTC text, and UTC ticks.
- Added latest-satellite benchmark coverage for timestamp and index-shape tuning.
- Added provider-aware included-index handling so providers without native included-index-column support can either append include columns to the key or ignore them.
- Set MySQL to ignore unsupported included index columns after measurements showed that appending `HashDiff` to the latest-satellite index key is counterproductive for the current MySQL workload.
- Improved the provider-neutral fallback writer so latest-satellite HashDiff checks query only requested parent hash keys instead of loading whole satellite tables.
- Added `IDataVaultReadService` for provider-neutral latest/as-of satellite reads.
- Added deferred capability baselines for multi-active satellite driving keys, PIT metadata projection, bridge metadata projection, provider capability profiles, API snapshots, and validation contracts.

## Compatibility Notes

- `DCoding.Data.DVault.Sqlite` remains the only provider package that had already been published before this release; the other provider packages are first coordinated publication candidates in `v0.5.0`.
- Provider-specific save strategies optimize clean contexts and supported request shapes. Unsupported shapes intentionally fall back to the provider-neutral writer.
- Oracle's optimized strategy remains scoped to clean hub/link insert batches; satellite batches are handled by the provider-neutral fallback in this release.
- `IDataVaultReadService` is intentionally narrow in `v0.5.0`: it covers latest/as-of satellite rows by parent hash key. PIT-backed read models, bridge traversal helpers, and provider-specific read strategies remain future work.
- Direct EF queries against generated shared-type tables remain supported for custom projections, diagnostics, and read shapes outside the read-service baseline.
