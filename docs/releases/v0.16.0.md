# DVault v0.16.0 Release Notes

Release: `v0.16.0 - Save And Read Telemetry`
Intended release date: 2026-05-20

## Package Scope

This is a coordinated release for the seven-package DVault NuGet family:

- `DCoding.Data.DVault`
- `DCoding.Data.DVault.Analyzers`
- `DCoding.Data.DVault.MySql`
- `DCoding.Data.DVault.Oracle`
- `DCoding.Data.DVault.Postgres`
- `DCoding.Data.DVault.Sqlite`
- `DCoding.Data.DVault.SqlServer`

All packages are version-aligned at `0.16.0`. Package publication remains a separate manual release activity; these notes do not record a NuGet push, package hashes, or final publication links.

## Highlights

- Added an opt-in save/read telemetry surface in the core package through `IDataVaultTelemetryObserver`, `DataVaultSaveTelemetrySummary`, and `DataVaultReadTelemetrySummary`.
- Added `AddDVaultTelemetry()` for the built-in `System.Diagnostics.Metrics` observer while keeping the default `AddDVault()` registration free of telemetry observers and counters.
- Emitted one bounded save telemetry summary for each explicit single or bulk save attempt, including request counts, hub/link/satellite operation counts, rows written, saved-record count, duration, selected strategy status, selected strategy name, and finite fallback-cause kinds.
- Emitted one bounded read telemetry summary for latest/current/as-of satellite reads, PIT reads, and bridge reads, including requested-key counts, returned-row counts, duration, selected strategy status, selected strategy name, and finite fallback-cause kinds.
- Kept failure telemetry bounded: failed attempts still report duration and finite result classification, but raw exception text, hash keys, record sources, metadata names, table names, and full diagnostics text are not emitted as counters or tags.
- Reused the established save/read strategy diagnostics vocabulary for telemetry status and fallback classification.

## Telemetry Contract

Telemetry is observational and opt-in. Applications that keep the current `AddDVault()` startup path do not need to configure listeners and keep the same save/read behavior. Applications that want built-in counters can add:

```csharp
services.AddDVault();
services.AddDVaultTelemetry();
```

The built-in meter name is `DCoding.Data.DVault`. Save instruments cover attempts, rows written, saved records, request counts, operation counts, duration, and provider-neutral fallback causes. Read instruments cover attempts, returned rows, requested keys, duration, and provider-neutral fallback causes. Tags are limited to stable low-cardinality values: operation kind, read family, success/failure outcome, provider name, selected strategy type name, strategy status, and finite fallback-cause enum names.

Applications that need code-facing hooks can register custom `IDataVaultTelemetryObserver` services. Observers receive `DataVaultSaveTelemetrySummary` and `DataVaultReadTelemetrySummary` values after each completed or failed explicit attempt. Observer failures are ignored so telemetry cannot change persistence or read behavior.

## Save Coverage

Save telemetry is emitted from the explicit save implementation path used by `IDataVaultSaveService.SaveAsync(DbContext, DataVaultSaveRequest)` and `IDataVaultSaveService.SaveAsync(DbContext, DataVaultBulkSaveRequest)`. Registry-backed and typed mapper save helpers delegate into the same explicit service, so they share the same telemetry boundary.

Each save summary identifies single-request versus bulk invocation, reports request and operation counts, reports rows written and saved-record counts for successful attempts, records elapsed duration, and classifies provider strategy dispatch with `DataVaultSaveStrategyDiagnosticsStatus` and `DataVaultSaveStrategyFallbackCauseKind`.

## Read Coverage

Read telemetry is emitted from the default explicit read service paths for latest/current/as-of satellite reads, PIT reads, and bridge reads. The implementation also covers typed latest/as-of satellite projection and bridge projection helper paths that use the default DVault read service instead of relying on an external service decorator.

Each read summary identifies the read family, reports requested parent or endpoint key counts, reports returned-row counts for successful attempts, records elapsed duration, and classifies provider strategy dispatch with `DataVaultReadStrategyDiagnosticsStatus` and `DataVaultReadStrategyFallbackCauseKind`.

## Out Of Scope

This release does not add telemetry for the SaveChanges metadata interceptor, diagnostics service calls themselves, design-time commands, migration guardrails, live-schema readers, PIT maintenance, bridge maintenance, or general EF Core activity outside explicit DVault save/read operations.
