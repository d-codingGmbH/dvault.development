# DVault v0.41.0 Release Notes

Release: `v0.41.0 - Provider Read Strategy Parity`
Release date: 2026-06-19

These notes define the coordinated v0.41.0 package and documentation baseline for DVault. The public release label maps to the consumer package versions `8.41.0` and `10.41.0`. The release closes provider read-strategy parity gaps for supported latest-satellite, PIT, and bridge read shapes while keeping DVault inside the existing EF Core library, explicit save/read service, provider-strategy, diagnostics, and benchmark-evidence boundary.

This release note does not record a NuGet push, package hashes, package-signing approval, release automation, new provider benchmark artifact triplets, stored-procedure deployment, runtime SQL artifact dispatch, automatic PIT or bridge maintenance, or widened provider capability guarantees.

## Implementation Scope

v0.41.0 extends and hardens provider read parity without adding new public read APIs:

- PostgreSQL, SQL Server, MySQL, Oracle, and DB2 provider packages now have diagnostics-gated read strategy coverage for supported latest-satellite, PIT, and bridge shapes.
- The shared relational PIT/bridge strategy covers bounded raw ADO reads with provider-specific quoting, parameter naming, batching, transaction participation, row normalization, and provider-neutral fallback boundaries.
- SQL Server, Oracle, and DB2 latest-satellite strategies now reliably override the shared latest-satellite interface path, so provider registration and DI dispatch use the intended provider-specific implementation.
- Provider-specific PIT and bridge raw reads now convert binary physical hash-key parameters and returned hash-key values through the same logical lowercase-hex boundary used by latest-satellite reads. Binary hash-key storage remains an explicit physical storage option; public request, read, diagnostics, and projection values remain lowercase hexadecimal strings.
- Parity tests compare provider-specific latest-satellite, PIT, bridge, and typed projection results against the provider-neutral `AddDVault()` fallback path, including binary hash-key storage for relational PIT and bridge reads.

## Provider Read Boundary

The accepted provider-read posture remains evidence-bounded:

- `AddDVaultSqlite()`, `AddDVaultPostgres()`, `AddDVaultSqlServer()`, `AddDVaultMySql()`, `AddDVaultOracle()`, and `AddDVaultDb2()` register diagnostics-gated read strategy candidates for supported latest-satellite, PIT, and bridge shapes.
- Latest-satellite provider optimization remains limited to supported hub-parent, non-multi-active satellite requests. Unsupported satellite parents, multi-active satellites, unknown providers, unregistered providers, declined strategy gates, or incomplete read-shape evidence fall back to provider-neutral reads.
- PIT and bridge reads consume already-maintained read-model tables. They do not run maintenance, schedule refreshes, create indexes, inspect provider plans, or repair stale rows.
- SQLite remains the only optimized latest-satellite row with completed timing in the root benchmark triplet.
- PostgreSQL, SQL Server, MySQL, Oracle, and DB2 latest-satellite rows are strategy-registration, diagnostics, smoke, or skipped-placeholder guidance until provider-configured timing lanes exist.
- PostgreSQL, SQL Server, MySQL, and Oracle PIT and bridge completed timing remains accepted only through the checked-in v0.32.0 smoke-read bundle. The root quick-baseline rows for optional external providers remain placeholders when connection strings are unset.
- DB2 latest-satellite, PIT, and bridge dispatch is repository-proven as diagnostics-gated and smoke-covered, but completed DB2 timing remains out of scope until a provider-configured benchmark artifact lane exists.

## Limitations And Non-Goals

v0.41.0 does not publish packages, record final publish approval, record package hashes, add package-signing evidence, or add release automation.

v0.41.0 does not define a consumer-facing `0.41.0` package version. Consumers should use the target-specific `8.41.0` or `10.41.0` package line.

v0.41.0 does not change the stable hash algorithm default, binary hash-key storage contract, analyzer target-framework boundary, or package dependency matrix beyond the release package versions.

v0.41.0 does not create new external-provider benchmark artifact triplets, completed non-SQLite latest-satellite timing, completed DB2 timing, automatic PIT or bridge maintenance, provider-specific physical-design promises, or universal provider performance guarantees. Future provider read or bulk optimizations must add their own diagnostics-selected behavior and preserved benchmark evidence before documentation can promote them from recommendation to completed timing claim.
