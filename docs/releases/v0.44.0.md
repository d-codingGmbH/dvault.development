# DVault v0.44.0 Release Notes

Release: `v0.44.0 - Optional Privacy Extension Foundation`
Release date: 2026-06-22

These notes define the coordinated v0.44.0 documentation, package-line, and optional privacy-extension baseline for DVault. The public release label maps to the consumer package versions `8.44.0` and `10.44.0`. There is no consumer-facing `0.44.0` package version.

This release note does not record a NuGet push, package hashes, package-signing approval, release automation, automatic privacy compliance, automatic encryption or redaction, provider-native encryption runtime behavior, row deletion, backup purge, PIT or bridge cleanup, key storage, key rotation, or key destruction.

## Optional Privacy Extension

The new `DCoding.Data.DVault.Privacy` package adds an explicit privacy seam for applications that want to keep personal-data handling near EF Core mapping without turning DVault into a compliance platform.

The shared v0.44 surface includes:

- `AddDVaultPrivacy(...)` for opt-in service registration.
- `DataVaultPrivacyOptions` for registering stable encrypted-payload aliases.
- `IDataVaultPrivacyConfiguration` for reading the configured aliases and caller-owned provider.
- `IDataVaultPrivacyKeyProvider` as the marker boundary for caller-owned key-policy integrations.
- `IDataVaultEncryptedPayloadKeyProvider` for caller-owned encrypted-payload conversion.
- `DataVaultEncryptedPayloadValueConverter` for explicit EF Core value conversion on a chosen payload property.
- `DataVaultEncryptedPayloadConversionRequest`, `DataVaultEncryptedPayloadConversionResult`, and `DataVaultEncryptedPayloadConversionDirection` as the provider-neutral request/result contract.

Encrypted payload conversion is fail-closed. Missing alias registration, missing key provider wiring, a marker-only key provider, declined conversion, or a conversion that returns a null value fails instead of silently storing plaintext or treating ciphertext as decrypted payload data.

The value-converter proof stores ordinary mapped values through EF Core. It keeps key lookup, key material, encryption/decryption policy, key rotation, key destruction timing, and operational privacy decisions owned by the consuming application.

## Model And Provider Boundaries

The model-first schema contract now includes additive `personalData` satellite-field metadata with a stable `encryptedPayloadAlias` handoff point. That metadata marks an existing satellite payload field for future opt-in privacy behavior; it does not replace the payload declaration, create provider columns, define keys, choose algorithms, generate DDL, or imply runtime encryption.

The architecture boundary documents the v1 crypto-shredding interpretation as caller-owned loss, withdrawal, or destruction of key material required to decrypt payloads for an alias. DVault does not own row deletion, historical rewrite, PIT or bridge cleanup, backup purge, archival purge, re-encryption, retention completion, legal erasure completion, or compliance attestation.

Provider-native encryption features remain guidance-only for this release. SQL Server TDE or Always Encrypted, PostgreSQL deployment encryption or `pgcrypto`, Oracle TDE or `DBMS_CRYPTO`, MySQL/MariaDB file or SQL crypto functions, SQLite encrypted-file builds, and DB2 native database encryption remain caller, operator, or database-admin responsibilities unless a later provider-specific opt-in contract explicitly owns them.

## Limitations And Non-Goals

v0.44.0 does not publish packages, record final publish approval, record package hashes, add package-signing evidence, or add release automation.

v0.44.0 does not define a consumer-facing `0.44.0` package version. Consumers should use the target-specific `8.44.0` or `10.44.0` package line.

v0.44.0 does not make an application GDPR/DSGVO-compliant. It does not add automatic encryption, pseudonymization, redaction, deletion, export filtering, retention workflows, subject-rights workflows, key storage, key rotation, key destruction, provider-native encryption DDL, or provider-native encryption runtime dispatch.

v0.44.0 does not change the public save/read API, public hash-key representation, stable hash default, provider dependency matrix, analyzer target-framework boundary, binary-first guidance, provider strategy dispatch semantics, or performance-evidence posture from the v0.43.0 provider and allocation baseline.
