## Boundary Shift From v0.26.0

v0.26.0 moved the coordinated public baseline forward around provider-tuning diagnostics, benchmark verifier evidence, migration guardrails, idempotency preflight, stored-procedure artifact boundaries, request-bound `ReadShape` diagnostics, and support-bundle-driven satellite, PIT, and bridge typed read helpers. That boundary remains intact and historical.

v0.27.0 moves the current public baseline forward for EF Core lifecycle analyzer guardrails. The analyzer catalog now documents `DMV1910` and `DMV1911` for generated shared-type-table misuse, plus `DMV1912` through `DMV1914` for high-confidence source-visible EF lifecycle misuse around caller-owned model-cache discriminators, compiled-model selection, and direct `AddDbContextPool<TContext>(...)` registrations.

This release is an analyzer and documentation boundary. It does not add runtime guards, runtime behavior changes, compiled-model generation, provider-specific lifecycle guarantees, cross-assembly inference, whole-application inference, provider-specific SQL guarantees, or new save/read runtime dispatch behavior.

## EF Lifecycle Analyzer Guardrails

The lifecycle analyzer slice is bounded to direct source evidence:

- `DMV1912` reports caller-owned DVault model-shape variation when the directly visible model-cache key path omits the same varying discriminator.
- `DMV1913` reports direct `UseModel(...)` selection when the same source visibly applies a compiled EF model to a DVault context whose realized model shape can vary.
- `DMV1914` reports direct `AddDbContextPool<TContext>(...)` registration when the target DVault context visibly has model-shape variation beyond one fixed options-only shape.

The supported non-diagnostic baselines remain:

- registry-backed `UseDataVaultMetadata(...)` paths, including app-default metadata, explicit `DataVaultMetadataModel`, explicit `DataVaultMetadataRegistry`, and imported `DataVaultModelImportResult` metadata;
- direct `ApplyDataVaultMetadata(...)` usage when the model shape is fixed for the context type and design-time flag, or when every caller-owned varying discriminator is visibly included in a caller-owned `IModelCacheKeyFactory`;
- fixed-shape `UseModel(runtimeModel)` usage when the runtime model was initialized from a design model that already contains the same DVault metadata projection;
- stable direct EF compiled queries over generated shared-type tables, using known table and column names with scalar parameters and deterministic projections;
- options-only `AddDbContextPool<TContext>(...)` usage for one fixed metadata/model shape, provider configuration, naming, schema, and profile.

The analyzer must skip ambiguous source. It does not expand arbitrary helpers, infer across assemblies, inspect generated compiled-model artifacts, prove provider-specific SQL behavior, diagnose pooled factory patterns, or treat compiled queries as compiled EF model selection.
