## Streaming Explicit Save Contract

The current public write boundary remains `IDataVaultSaveService`. v0.19.0 adds the documented chunked overload beside the existing single-request and ordered-bulk overloads:

```csharp
Task<DataVaultSaveResult> SaveAsync(
    DbContext dbContext,
    DataVaultChunkedSaveRequest request,
    CancellationToken cancellationToken = default);
```

`DataVaultChunkedSaveRequest` carries caller-ordered `DataVaultSaveChunk` values. Each chunk carries an ordered, finite collection of ordinary `DataVaultSaveRequest` values, so contained requests keep the same explicit load timestamp, record source, metadata resolution, hash-key, hash-diff, hub, link, and satellite rules as existing explicit save requests.

The service processes chunks in caller-supplied order, requests inside each chunk in caller-supplied order, and operations inside each request in the existing hub, link, then satellite order. Empty chunk sequences and empty chunks are no-ops. The cancellation token is observed before continuing to later chunks.

The caller owns the `DbContext`, current or ambient transaction, and cancellation token. Chunked execution participates in the caller's current transaction and does not create, commit, roll back, or suppress transactions. Callers that need all-or-nothing behavior across chunks should open the transaction before invoking the chunked save and decide how to handle cancellation or failure.

The provider-neutral retained-state implementation keeps satellite continuity state for one explicit chunked-save attempt. The default retained-state limit is `10000` satellite series per attempt. When that limit is reached, DVault records the finite `RetainedSatelliteSeriesLimitReached` fallback cause and `RetainedSatelliteSeriesLimitExceeded` unsupported-shape classification, clears retained state, and falls back to bounded per-chunk persisted latest-state lookup.

`DataVaultSaveTelemetrySummary` reports chunk count, processed chunk count, retained-state current and high-water counts, finite retained-state fallback causes, unsupported-shape classifications, and chunked transaction guidance. It does not expose raw hash keys, payload values, or per-parent retained-state entries.

## Migration Guidance

Keep `DataVaultBulkSaveRequest` when a loader already materializes the full ordered request set. It remains the straightforward compatibility path for existing batch loaders and for registry-backed callers that use `DataVaultRegistryBulkSaveRequest`.

Use `DataVaultChunkedSaveRequest` only when the loader needs bounded chunking without changing explicit timestamps, record sources, request ordering, hash semantics, or caller-owned transaction behavior. Build chunks from ordinary ordered `DataVaultSaveRequest` values and preserve the same logical order the equivalent bulk request would have used.

Do not infer provider-native chunk execution, staged provider bulk ingestion, file ingestion, background work, scheduler behavior, CDC ingestion, or implicit `SaveChanges` persistence from the chunked API. Those remain outside the current public boundary.

## Compatibility Notes

- Existing `SaveAsync(DbContext, DataVaultSaveRequest, ...)` and `SaveAsync(DbContext, DataVaultBulkSaveRequest, ...)` callers remain compatible.
- `DataVaultBulkSaveRequest.Requests` ordering remains caller order, and `DataVaultSaveResult.SavedRecords` remains deterministic relative to caller-supplied save order.
- `DataVaultChunkedSaveRequest` is additive. Contained `DataVaultSaveRequest` values use the same validation, metadata resolver, hash-key, hash-diff, hub, link, and satellite behavior as existing explicit save requests.
- Existing provider-specific save strategies remain optimizations around the same public save contract. Declined or unsupported shapes fall back without changing caller-visible semantics.
- Package publication remains manual and coordinated across all seven package ids.

## Known Limitations

- Provider-native chunk execution and staged provider bulk ingestion are not v0.19.0 public behavior.
- The benchmark evidence is the root SQLite local provider-neutral summary rows. It does not assert provider-specific chunk SQL shape, provider-specific chunk batching, external-provider chunk timings, or a before-and-after streaming optimization bundle.
- A chunked save that exceeds the retained satellite-series limit records bounded fallback and unsupported-shape classifications and uses per-chunk persisted latest-state lookup. It does not retain unbounded state to preserve streaming semantics.
- DVault still does not ship release automation, publish packages automatically, provide package credentials, or replace the final approval record required by `docs/manual-nuget-publication.md`.
