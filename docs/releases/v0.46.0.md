# DVault v0.46.0 Release Notes

Release: `v0.46.0 - Reserved Interactive Provider Optimization`
Release date: 2026-06-23

These notes record the coordinated v0.46.0 provider optimization closure, documentation, validation, and package-line baseline for DVault. The public release label maps to the consumer package versions `8.46.0` and `10.46.0`. There is no consumer-facing `0.46.0` package version.

Use exactly one line in a consumer project. Do not mix `8.46.0` and `10.46.0` packages in one project, install example, restored target, or publish approval.

## Optimization Closure

The v0.46.0 work closes the manually coordinated provider optimization pass that followed the v0.45.0 PIT maintenance exploration. The release keeps DVault focused as an EF Core library family: save/read services, provider strategies, diagnostics, evidence, and documentation. It does not add schedulers, provisioning, dashboards, deployment automation, or a platform surface.

The main implementation changes are:

- The shared relational PIT/bridge read strategy now keeps the provider connection open for the full read pipeline, applies PIT `LoadTimestamp <= @asOf` filtering in SQL, narrows satellite replay reads by parent key and timestamp window, and preserves the provider-neutral ordinal-signature semantics for row assembly.
- Oracle read strategies configure ODP.NET command-level LOB prefetch and fetch-buffer settings when the provider command exposes those properties.
- DB2 optimized save keeps the clean-context set-based path and raises the measured command row cap to 1000 while preserving transaction participation and duplicate-ignore semantics.
- SQL Server, PostgreSQL, MySQL, Oracle, and DB2 save/latest/PIT/bridge timing evidence is captured under the provider optimization closure bundle.
- MySQL retains separate evidence boundaries for retained multi-row save, bounded staged save, and deliberate large mixed provider-neutral fallback.

## Validation

The release validation lane is:

```sh
dotnet build DVault.slnx --nologo
dotnet test DVault.slnx --nologo
bash tools/pack-release-packages.sh
bash tools/verify-packages.sh
bash tools/check-format.sh
```

Package validation checks the expected `8.46.0` and `10.46.0` artifact set, package metadata, dependency groups, analyzer asset placement, XML documentation, symbol packages, README installation guidance, and stale-version guardrails. Package creation and verification do not imply signed NuGet publication.

## Non-Goals

v0.46.0 does not publish packages, record final publish approval, record package hashes, add package-signing evidence, or add release automation.

v0.46.0 does not define a consumer-facing `0.46.0` package version. Consumers should use the target-specific `8.46.0` or `10.46.0` package line.

v0.46.0 does not add automatic PIT or bridge maintenance, read-time refresh, background scheduling, EF `SaveChanges` interception, provider-specific bridge maintenance, provider provisioning, provider-specific physical-design requirements, raw SQL plan guarantees, runtime SQL artifact dispatch, or provider support outside the evidence-linked rows.

v0.46.0 does not turn the v0.45.0 PIT maintenance prototypes into benchmark-backed performance claims. Provider-maintenance timing claims still require preserved benchmark artifacts for the exact maintenance workload, provider, run context, and fallback rows.
