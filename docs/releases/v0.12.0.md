# DVault v0.12.0 Release Notes

Release: `v0.12.0 - Analyzer and Generator Ergonomics`
Intended release date: 2026-05-17

## Package Scope

This is a coordinated release for the seven-package DVault NuGet family:

- `DCoding.Data.DVault`
- `DCoding.Data.DVault.Analyzers`
- `DCoding.Data.DVault.MySql`
- `DCoding.Data.DVault.Oracle`
- `DCoding.Data.DVault.Postgres`
- `DCoding.Data.DVault.Sqlite`
- `DCoding.Data.DVault.SqlServer`

All packages are version-aligned at `0.12.0`. Package publication remains a separate manual release activity; these notes do not record a NuGet push, package hashes, or final publication links.

## Highlights

- Carried forward the DMV1901 and DMV1902 Code-First analyzer baseline for unsupported selector shapes and duplicate logical member declarations.
- Added bounded code fixes for directly expandable DMV1901 anonymous-object member selectors and later duplicate DMV1902 declarations.
- Added source-generated mapper helper support for compile-time mapping declarations in `DCoding.Data.DVault`.
- Added DMV1950 through DMV1955 diagnostics for malformed mapping declarations, missing generated row bindings, invalid source members, duplicate binding order or names, and duplicate link produced participant names.
- Kept generated helpers on the existing explicit save boundary: generated mappers construct registry-backed save operations and callers still provide `loadTimestamp`, `recordSource`, `DbContext`, and `IDataVaultSaveService` orchestration.
- Refreshed README, quickstart, analyzer-package, production-adoption, and model-first governance guidance for the `0.12.0` public baseline.

## Analyzer And Code Fix Surface

`DCoding.Data.DVault.Analyzers` remains optional developer tooling. Consumers should reference it with `PrivateAssets="all"` in projects that own DVault Code-First declarations or compile-time mapping declarations.

The carried-forward analyzer baseline remains:

- `DMV1901` reports unsupported selector shapes passed to `BusinessKey(...)`, `Payload(...)`, or `DrivingKey(...)`.
- `DMV1902` reports duplicate logical member declarations in the same applicable Code-First builder lambda scope.

The v0.12 code-fix layer is intentionally bounded. DMV1901 fixes are offered only when an anonymous-object selector can be mechanically expanded into repeated same-verb single-member calls in source order. The fix is not offered for selector variables, indirect selectors, computed selectors, nested selectors, method calls, collection-valued selectors, or mixed anonymous-object selectors that are not mechanically expandable. DMV1902 fixes remove the later duplicate declaration and keep the first declaration authoritative.

## Generated Mapper Surface

The source generator recognizes public compile-time mapping attributes from `DCoding.Data.DVault`:

- `DataVaultHubMappingAttribute` plus ordered `DataVaultBusinessKeyBindingAttribute` values.
- `DataVaultLinkMappingAttribute` plus ordered `DataVaultLinkParticipantBindingAttribute` values.
- `DataVaultHubSatelliteMappingAttribute` plus parent hash-key, hash-diff, ordered payload, and optional ordered driving-key bindings.

Generated code implements the existing `IDataVaultHubMapper<TSource>`, `IDataVaultLinkMapper<TSource>`, or `IDataVaultSatelliteMapper<TSource>` contracts and constructs `DataVaultRegistry*SaveOperation` values. It does not execute EF models, register mappings at runtime, derive hash keys or hash diffs, save data implicitly, or hide the caller-owned `loadTimestamp` and `recordSource` boundary.

## Mapping Diagnostics

The v0.12 mapping diagnostics are:

- `DMV1950`: one source type declares an ambiguous mapping shape.
- `DMV1951`: a required generated row binding is missing.
- `DMV1952`: a binding references an invalid source member.
- `DMV1953`: duplicate binding order values are present.
- `DMV1954`: duplicate binding names are present.
- `DMV1955`: a link mapping repeats a participant hub name.

These diagnostics protect generator input shape. They do not replace DVault model governance, runtime metadata validation, provider drift checks, or application-owned save validation.

## Compatibility Notes

- Existing Code-First, metadata-first, and model-first declaration paths remain additive alternatives for different ownership needs.
- Existing `IDataVaultSaveService`, typed read helpers, provider save strategies, model-first governance APIs, analyzer diagnostics, and opt-in `SaveChanges` metadata interceptor behavior remain compatible.
- Manual typed mappers and generated mappers share the same registry-backed save-operation boundary.
- Provider packages still depend on the aligned `DCoding.Data.DVault` package version.
- The analyzer package remains optional developer tooling and should usually be referenced with `PrivateAssets="all"`.
- The design-time command surface is reusable library code, not a standalone executable package.

## Known Limitations

- The analyzer package is not a complete Data Vault model validator.
- Source-generated mapper helpers do not compute hash keys, compute hash diffs, execute saves, select EF providers, or create metadata at runtime.
- Runnable generator-based consumer examples are not included in this release note; the checked-in quickstarts remain metadata-first.
- Startup-project and target-project splits for design-time discovery remain outside the documented v1 workflow.
- DVault does not provide a first-party `dotnet ef` command shim, EF CLI interception, automatic migration execution, or automatic schema repair.
- Live-schema readers are bounded to DVault-owned table, column, primary-key, and index metadata.
