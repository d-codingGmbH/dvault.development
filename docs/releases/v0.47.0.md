# DVault v0.47.0 Release Notes

Release: `v0.47.0 - Provider Maintenance Documentation Baseline`
Release date: 2026-06-24

These notes record the coordinated v0.47.0 provider-maintenance documentation, evidence-boundary, validation, and package-line baseline for DVault. The public release label maps to the consumer package versions `8.47.0` and `10.47.0`. There is no consumer-facing `0.47.0` package version.

## Package Lines

| Package version line | Target framework | EF Core line |
| --- | --- | --- |
| `8.47.0` | `net8.0` | EF Core 8 |
| `10.47.0` | `net10.0` | EF Core 10 |

Use exactly one line in a consumer project. Do not mix `8.47.0` and `10.47.0` packages in one project, install example, restored target, or publish approval.

## Provider Maintenance Baseline

The v0.47.0 documentation baseline carries forward the v0.46.0 provider optimization closure timing evidence while aligning the PIT maintenance guidance with the current source and test backed repository behavior:

- PostgreSQL still contributes `PostgresDataVaultPitMaintenanceStrategy` for clean full rebuilds of ordinary hub-parent PITs, shared-driving-key multi-active hub-parent PITs, and link-parent non-multi-active PITs when no caller transaction is already active.
- SQL Server still uses `SqlServerDataVaultPitMaintenanceService` for clean ordinary hub-parent full rebuilds only.
- MySQL now contributes `MySqlDataVaultPitMaintenanceStrategy` for clean ordinary hub-parent full rebuilds on the official `MySql.EntityFrameworkCore` provider only.
- Oracle PIT maintenance remains deferred.
- DB2 PIT maintenance remains provider-neutral until the accepted future ordinary hub-parent full-rebuild lane is implemented.
- Bridge maintenance remains provider-neutral and outside provider push-down scope.

All provider-maintenance lanes remain explicit caller-invoked work. Saves, reads, EF `SaveChanges`, provider startup, and background scheduling do not refresh PIT or bridge rows implicitly.

## Evidence And Claim Boundaries

Use [Provider Optimization Evidence Matrix](../plans/provider-optimization-evidence-matrix.md), [Provider Optimization Gap Matrix](../plans/provider-optimization-gap-matrix.md), [Performance Profiles](../performance-profiles.md), and [DVault V1 PIT And Bridge Boundary](../architecture/dvault-v1-pit-bridge-boundary.md) as the adopter-facing lookup surfaces.

The completed provider timing evidence remains the checked-in 2026-06-23 provider optimization closure bundle under [`artifacts/benchmarks/06FF0000000000000000000000-provider-optimization-closure-20260623/`](../../artifacts/benchmarks/06FF0000000000000000000000-provider-optimization-closure-20260623/). Those rows cover provider-native save, latest-satellite read, PIT read, and bridge read scenarios for PostgreSQL, SQL Server, MySQL, Oracle, and DB2.

PIT and bridge read rows are read-side evidence over already-maintained read-model rows. They do not prove PIT maintenance timing, bridge maintenance timing, automatic refresh, or provider SQL maintenance execution.

Provider-maintenance timing claims still require a completed `pit-full-rebuild-maintenance` benchmark row, preserved `benchmark-summary.md`, `benchmark-summary.csv`, and `benchmark-summary.json` artifacts from the same run, run context, selected strategy or fallback posture, and bounded fallback causes. Source and test backed PostgreSQL, SQL Server, and MySQL maintenance availability must not be promoted into benchmark-backed performance wins without those artifacts.

## Validation

The release validation lane is:

```sh
dotnet build DVault.slnx --nologo
dotnet test DVault.slnx --nologo
bash tools/pack-release-packages.sh
bash tools/verify-packages.sh
bash tools/check-format.sh
```

Package validation checks the expected `8.47.0` and `10.47.0` artifact set, package metadata, dependency groups, analyzer asset placement, XML documentation, symbol packages, README installation guidance, and stale-version guardrails. Package creation and verification do not imply signed NuGet publication.

## Non-Goals

v0.47.0 does not publish packages, record final publish approval, record package hashes, add package-signing evidence, or add release automation.

v0.47.0 does not define a consumer-facing `0.47.0` package version. Consumers should use the target-specific `8.47.0` or `10.47.0` package line.

v0.47.0 does not run new benchmarks, generate new evidence artifacts, or convert skipped-placeholder, diagnostics-only, smoke-only, storage-footprint, or source/test-backed maintenance statements into measured timing claims.

v0.47.0 does not add automatic PIT or bridge maintenance, read-time refresh, background scheduling, EF `SaveChanges` interception, provider-specific bridge maintenance, Oracle PIT maintenance, DB2 PIT maintenance implementation, provider provisioning, provider-specific physical-design requirements, raw SQL plan guarantees, runtime SQL artifact dispatch, or provider support outside the evidence-linked rows.
