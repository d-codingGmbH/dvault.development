# DVault v0.48.0 Release Notes

Release: `v0.48.0 - Privacy Preflight and Adoption Ergonomics`
Release date: 2026-06-26

These notes record the coordinated v0.48.0 privacy preflight, adoption documentation, validation, and package-line baseline for DVault. The public release label maps to the consumer package versions `8.48.0` and `10.48.0`. There is no consumer-facing `0.48.0` package version.

## Package Lines

| Package version line | Target framework | EF Core line |
| --- | --- | --- |
| `8.48.0` | `net8.0` | EF Core 8 |
| `10.48.0` | `net10.0` | EF Core 10 |

Use exactly one line in a consumer project. Do not mix `8.48.0` and `10.48.0` packages in one project, install example, restored target, or publish approval.

## Privacy Preflight

v0.48.0 tightens the optional privacy extension from an opt-in proof into a reviewable preflight surface:

- `DataVaultPrivacyCoverageReporter.Analyze(...)` creates deterministic, redaction-safe alias coverage reports from a configured `DbContext` or EF `IModel` without querying the database.
- Registered encrypted-payload aliases are classified as `covered` or `registered-but-unmapped`, and the report records key-provider posture as `none`, `marker-only`, or `encrypted-payload-capable`.
- Personal-data diagnostics keep the v1 severity split: missing opt-in privacy proof remains advisory with `personal-data-privacy-proof-missing`, while configured but unusable alias, key-provider, proof, or converter coverage is fail-closed with `personal-data-privacy-coverage-unusable`.
- A marked payload field counts as covered only when the alias proof is usable and the EF model shows `DataVaultEncryptedPayloadValueConverter` wired to the same encrypted-payload alias on that exact mapped payload property.

The privacy lane remains explicit and provider-neutral. DVault does not own key creation, storage, rotation, destruction, retention, deletion, backup purge, legal-erasure completion, compliance attestation, provider-native encrypted DDL, provider SQL crypto functions, provider encryption capability probing, or runtime dispatch based on native encryption availability.

## Adoption And Examples

The SQLite quickstart now contains a small local privacy proof that combines binary-first DVault setup with explicit `AddDVaultPrivacy(...)` registration, one caller-owned encrypted payload key provider, and one `DataVaultEncryptedPayloadValueConverter` mapped payload round trip.

The production adoption checklist now has a dedicated privacy preflight section that tells adopters how to review alias coverage, `personalData` markers, key-provider posture, advisory versus fail-closed diagnostics, and provider-native encryption caveats before promoting an opt-in privacy proof.

Provider-native encryption features remain guidance-only examples for the finite repository-backed provider set: SQLite, PostgreSQL, SQL Server, MySQL, Oracle, and DB2. Any future native encryption support must be scoped as a separate provider-specific contract and ticket.

## Analyzer Baseline

The analyzer retargeting audit keeps the existing package shape: both visible package lines carry the same `net10.0` analyzer asset, and validated analyzer consumption uses a `.NET 10 SDK` build host, including `net8.0` projects on the `8.48.0` package line. v0.48.0 does not claim pure `.NET 8 SDK` analyzer consumption.

## Validation

The release validation lane is:

```sh
dotnet build DVault.slnx --nologo
dotnet test DVault.slnx --nologo
bash tools/pack-release-packages.sh
bash tools/verify-packages.sh
bash tools/check-format.sh
```

Package validation checks the expected `8.48.0` and `10.48.0` artifact set, package metadata, dependency groups, analyzer asset placement, XML documentation, symbol packages, README installation guidance, and stale-version guardrails. Package creation and verification do not imply signed NuGet publication.

## Non-Goals

v0.48.0 does not publish packages, record final publish approval, record package hashes, add package-signing evidence, or add release automation.

v0.48.0 does not define a consumer-facing `0.48.0` package version. Consumers should use the target-specific `8.48.0` or `10.48.0` package line.

v0.48.0 does not add automatic privacy execution, automatic encryption or redaction, key lifecycle ownership, compliance guarantees, provider-native encryption behavior, automatic crypto-shredding execution, retention or deletion workflows, PIT or bridge cleanup workflows, provider provisioning, or broader analyzer compatibility claims.
