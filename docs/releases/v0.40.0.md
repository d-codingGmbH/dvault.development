# DVault v0.40.0 Release Notes

Release: `v0.40.0 - Provider Bulk Strategy Expansion`
Release date: 2026-06-16

These notes define the coordinated v0.40.0 package and documentation baseline for DVault. The public release label maps to the consumer package versions `8.40.0` and `10.40.0`. The release keeps provider bulk work inside the existing EF Core-oriented save-service and provider-strategy boundary, and it records the current implementation/evidence posture without turning DVault into a platform, scheduler, deployment tool, or automatic provider-provisioning layer.

This release note does not record a NuGet push, package hashes, package-signing approval, release automation, new provider benchmark artifact triplets, stored-procedure deployment, runtime SQL artifact dispatch, or widened provider capability guarantees.

## Implementation Scope

v0.40.0 hardens the shared provider-bulk and benchmark support surface without adding a new public runtime API:

- Shared-type string equality filters now de-duplicate input values and build a balanced `OrElse` predicate tree. This keeps large generated batch predicates shallower while preserving the existing EF Core query shape and semantics.
- Unit coverage now checks the large-batch predicate shape, including duplicate removal and bounded `OrElse` depth.
- Benchmark database setup now routes table creation through `IBenchmarkDatabase.EnsureCreatedAsync` so provider-specific benchmark databases can own their creation behavior.
- DB2 benchmark setup uses relational table creation for the existing database, cleans up both quoted and uppercase produced table names, and accepts both current IBM DB2 connection type names used by the provider packages.
- Benchmark scenarios now call the database abstraction for schema creation instead of directly calling `context.Database.EnsureCreatedAsync`, which keeps SQLite, PostgreSQL schema isolation, shared external providers, and DB2 aligned under the same lifecycle contract.

## Provider Bulk Boundary

Provider bulk work remains behind `IDataVaultSaveService` and the registered `IDataVaultProviderSaveStrategy` implementations. The release does not add automatic `SaveChanges` interception, background ingestion, stored-procedure runtime dispatch, generated deployable SQL payloads, automatic routing outside the save-service dispatcher, or database provisioning.

The accepted provider-bulk posture remains diagnostics-gated and evidence-bounded:

- clean EF Core context
- provider-name match
- caller-owned transaction behavior
- ordered explicit bulk batches or chunk-internal ordered batches
- provider-neutral fallback when a provider, shape, gate, or benchmark-evidence condition is not met
- no promotion of skipped optional-provider rows into completed timing evidence

PostgreSQL, SQL Server, MySQL, Oracle, and DB2 provider claims should continue to cite the existing evidence matrix, gap matrix, performance guide, and benchmark artifact bundles. v0.40.0 does not rerun external-provider benchmarks and does not add new completed timing claims by itself.

Package creation and verification do not imply signed NuGet publication.

## Limitations And Non-Goals

v0.40.0 does not publish packages, record final publish approval, record package hashes, add package-signing evidence, or add release automation.

v0.40.0 does not define a consumer-facing `0.40.0` package version. Consumers should use the target-specific `8.40.0` or `10.40.0` package line.

v0.40.0 does not change the stable hash algorithm default, binary hash-key storage contract, analyzer target-framework boundary, or package dependency matrix beyond the release package versions.

v0.40.0 does not create new external-provider benchmark artifact triplets or universal provider performance guarantees. Future provider bulk or read optimizations must add their own diagnostics-selected behavior and preserved benchmark evidence before documentation can promote them from recommendation to completed timing claim.
