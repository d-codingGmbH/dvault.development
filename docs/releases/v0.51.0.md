# DVault v0.51.0 Release Notes

Release: `v0.51.0 - Release Notes and Package Validation Baseline`
Release date: 2026-07-01

These notes record the coordinated v0.51.0 documentation, validation, package-verifier, and package-line baseline for DVault. The public release label maps to the consumer package versions `8.51.0` and `10.51.0`. There is no consumer-facing `0.51.0` package version.

## Package Lines

| Package version line | Target framework | EF Core line |
| --- | --- | --- |
| `8.51.0` | `net8.0` | EF Core 8 |
| `10.51.0` | `net10.0` | EF Core 10 |

Use exactly one line in a consumer project. Do not mix `8.51.0` and `10.51.0` packages in one project, install example, restored target, or publish approval.

## Analyzer Compatibility Baseline

`DCoding.Data.DVault.Analyzers` remains a local build-time package reference with `PrivateAssets="all"`. The analyzer package ships one `netstandard2.0` analyzer asset under `analyzers/dotnet/cs/` for both visible package lines, and supported analyzer consumption uses either a `.NET 8 SDK` or `.NET 10 SDK` build host.

v0.51.0 preserves one analyzer package id and one reviewed asset path. Consumers can target `net8.0` with the `8.51.0` line and run the analyzer package on a `.NET 8 SDK` host, while the corresponding `.NET 10 SDK` host proof remains covered for the `10.51.0` line.

## Package Verification

`bash tools/pack-release-packages.sh` creates the coordinated package artifacts under `artifacts/packages/` for both visible package lines. `bash tools/verify-packages.sh` validates the expected package counts, package ids, versions, filenames, metadata, README install guidance, XML documentation, analyzer assets, provider dependencies, DB2 dependency alignment, EF Core dependency lines, symbol packages, and stale package artifacts.

Package verification preserves stale-version guardrails for current-package guidance. Packaged README install guidance must not publish `0.51.0` from the release label, must not use stale `8.50.0` or `10.50.0` package lines, must not mix the `8.51.0` and `10.51.0` lines, and must retain the dual `.NET 8 SDK` / `.NET 10 SDK` analyzer build-host guidance plus the one `netstandard2.0` analyzer asset contract.

Package creation and verification do not imply signed NuGet publication or final publish approval.

## Validation

The release validation lane is:

```sh
dotnet build DVault.slnx --nologo
dotnet test DVault.slnx --nologo
bash tools/pack-release-packages.sh
bash tools/run-analyzer-package-smoke.sh 8
bash tools/run-analyzer-package-smoke.sh 10
bash tools/verify-packages.sh
bash tools/check-format.sh
```

The local validation baseline requires both .NET 8 and .NET 10 SDKs. Helper projects may stay on `net10.0`; the packaging lane proves the consumer `net8.0` and `net10.0` package outputs, and the analyzer smoke lanes prove packed analyzer consumption on both SDK hosts.

## Non-Goals

v0.51.0 does not publish packages, record final publish approval, record package hashes, add package-signing evidence, or add release automation.

v0.51.0 does not define a consumer-facing `0.51.0` package version. Consumers should use the target-specific `8.51.0` or `10.51.0` package line.

v0.51.0 does not change analyzer package shape, package ids, dependency-major baselines, provider scope, manual-publication workflow, provider performance claims, provider provisioning, analyzer compatibility beyond the `.NET 8 SDK` and `.NET 10 SDK` build-host boundary, automatic privacy execution, provider-native encryption behavior, automatic hash-key migration execution, dependent child key modeling, model-first same-hub typed mapper generation, effectivity-specific fluent APIs, implicit persistence, or automatic PIT or bridge maintenance.
