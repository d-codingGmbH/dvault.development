# DVault v0.22.0 Release Notes

Release: `v0.22.0 - Typed Read And Hash Governance Documentation`
Intended release date: 2026-05-28

These notes define the v0.22.0 documentation boundary. They do not record a NuGet push, package hashes, final publication links, release approval, support-bundle publication, or generated approval snapshots by themselves.

## Package Scope

This is a coordinated release for the seven-package DVault NuGet family:

- `DCoding.Data.DVault`

## Boundary Shift From v0.21.0

v0.21.0 moved the public documentation baseline forward for explicit PIT and bridge maintenance, reads, diagnostics, and SQLite optimized read dispatch. That boundary remains intact and historical.

v0.22.0 moves the documentation baseline forward for support-bundle-driven typed satellite read helpers and stable hash governance. It does not add new runtime APIs, new public API snapshot infrastructure, analyzer-package public API approval, generator approval snapshots, package-publication automation, support-bundle routing, PIT helper generation, bridge helper generation, provider-specific SQL generation, or dynamic read-request compilation.

## Typed Satellite Helper Boundary

Typed read-model generation is opt-in through `DVaultGenerateTypedReadModels=true`. The generator consumes exactly one authoritative `dvault.support-bundle.v1` additional file exported after Code-First, metadata-first, or model-first declarations have been projected into EF/DVault metadata. Consumers may pin `DVaultTypedReadModelMetadataSourceFingerprint` to fail the build when the reviewed metadata-source fingerprint drifts.

The generator emits helpers only for supported satellites:

- hub-parent satellites.
- link-parent satellites.
- deterministic multi-active satellites whose driving keys and payload values are strings after projection.

For those supported satellites, the generated surface includes `{SatelliteProducedName}ReadModel` plus `Read...CurrentAsync`, `Read...LatestAsync`, and `Read...AsOfAsync` extension methods over `IDataVaultReadService`. The helpers remain ergonomics over the existing read service and projected support-bundle metadata.

The generator does not parse raw `dvault.model.v1` additional files directly, does not infer helpers from source-visible Code-First callbacks, does not infer helpers from literal `DataVaultMetadataModel` declarations, does not emit PIT or bridge helpers, does not generate provider-specific SQL, and does not compile dynamic read requests. PIT and bridge shapes remain runtime read-service and diagnostics surfaces.

Generator behavior is backed by [DataVaultTypedReadModelSourceGeneratorTests.cs](../../tests/DCoding.Data.DVault.Tests/Analyzers/DataVaultTypedReadModelSourceGeneratorTests.cs), including satellite helper emission and `DMV1960` through `DMV1969` diagnostic coverage.

## Support-Bundle Workflow

`dvault.model.v1` and `dvault.support-bundle.v1` are workflow artifact contracts, not repository-root baseline files. A consumer-owned workflow should review the model artifact, import and project it into EF/DVault metadata, run drift or validation checks, and export a redacted support bundle through the consumer-hosted design-time command when generator input or diagnostic evidence is needed.

The reusable command host does not publish support bundles, attach them to tickets, archive them, route them between projects, intercept `dotnet ef`, or ship a standalone `dvault` CLI. Support-bundle output paths, storage, retention, transport, and approval policies remain consumer-owned.

## Stable Hash Governance

The default stable hash algorithm id remains `sha256-v1`. The compatibility contract is SHA-256 over UTF-8 normalized input bytes without a byte order mark, with lowercase 64-character hexadecimal digest output. The shared normalizer owns canonical scalar encodings, line ending normalization, invariant formatting, and ordinal structured-field ordering before bytes are hashed.

Provider packages may optimize write transport, staging, existence checks, and insert shapes, but they must preserve the registered stable hash normalizer and service semantics. Provider SQL hashing, provider-specific canonicalization, process-local salts, timestamps, current culture, serializer iteration order, and machine-local side effects remain outside the compatibility boundary.

The stable hash evidence surfaces are [Stable Hashing Contract](../plans/stable-hashing-contract.md) and [StableHashServiceTests.cs](../../tests/DCoding.Data.DVault.Tests/Unit/StableHashServiceTests.cs).

## Alternatives And Compatibility

Dynamic `IDataVaultReadService` requests remain the documented default for runtime-built read shapes, PIT reads, bridge reads, and caller-selected projectors. Consumer-owned EF compiled queries remain appropriate for stable direct EF shared-type-table expressions with generated names, scalar parameters, `EF.Property<T>(...)`, and deterministic projections, as documented in [DVault EF Compiled Compatibility](../architecture/dvault-ef-compiled-compatibility.md).

Existing explicit save, bulk save, chunked save, telemetry, diagnostics, model-first import/export/drift, PIT maintenance, bridge maintenance, public API snapshot, and provider package boundaries remain compatible with the prior documentation baseline.

## Documentation Updates

The v0.22.0 documentation baseline is reflected in `README.md`, `src/DCoding.Data.DVault.Analyzers/README.md`, `docs/model-first-governance.md`, `docs/production-adoption-checklist.md`, and this release note.

Those documents should tell one consistent story: typed helper generation is support-bundle-driven and satellite-only; raw model artifacts are reviewed workflow inputs, not direct generator inputs; support-bundle transport is consumer-owned; PIT and bridge helpers are not emitted; dynamic read requests and consumer-owned compiled EF queries remain alternatives; stable hash compatibility is governed by `sha256-v1`; and public API references are limited to the existing core and provider snapshot surface.

The repository validation command baseline remains the [README local validation](../../README.md#local-validation) section:

```sh
dotnet build DVault.slnx --nologo
dotnet test DVault.slnx --nologo
bash tools/check-format.sh
```

## Limitations

v0.22.0 documentation does not implement raw `dvault.model.v1` generator parsing, PIT typed helpers, bridge typed helpers, provider-specific generated SQL, dynamic request compilation, support-bundle publication, standalone CLI packaging, analyzer-package public API snapshots, dedicated generator approval snapshots, automatic support-bundle routing, automatic package publication, provider SQL hashing, or changes to the stable hash algorithm.

Future work that adds any of those capabilities should land under additive capability or evidence tickets and later release notes rather than widening the v0.22.0 boundary retroactively.
